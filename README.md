# hl-douyin-plugin

TRSS-Yunzai 抖音自动续火插件。定时给抖音好友发消息保住火花，跑完把结果推到群里，配套一个带临时验证码鉴权的 Web 面板做可视化管理。

移植自 `douyin-auto-spark`（Playwright / TypeScript），改写为 Yunzai 插件：浏览器自动化换成仓库里已有的 puppeteer，定时改成可热更新的 cron，账号按机器人隔离，Cookie 加密落盘。

## 特性

- **定时续火** — 6 位 cron（秒在最前），锅巴或指令改完立即生效，不用重启
- **跳过今日已续火** — 抖音火花一天只认一次，已成功的账号定时任务直接跳过，可开关
- **好友改名不断火** — 续火目标存 `主名 + 别名 + 备注`，主名搜不到自动试别名，命中后把新名提为主名
- **结果推送** — 跑完自动发群 / 私聊 / 两者，支持多群、跨机器人、详细/简要两种模式、仅失败时推送
- **Web 可视化面板** — 账号管理、给指定好友手动发信、拉取会话列表、扫码登录、改配置、看状态与审计
- **远程过验证** — 抖音扫码后追加身份验证时，私信一个临时链接，在里面看着那台浏览器的画面直接点/拖/打字把验证过掉
- **三种登录方式** — 扫码自动抓 Cookie、私聊粘贴、发 txt 文件（QQ 输入框会截断超长 Cookie）
- **多机器人隔离** — 账号按 botId 分文件存储，面板会话只能进入「你是主人」的那些机器人
- **锅巴配置** — 全部配置项都在锅巴面板里可视化编辑，账号与 Cookie 也在里面增删
- **文本出图** — 帮助 / 设置 / 状态渲染成图片，渲染失败自动降级成文字
- **访问频次控制** — 拦截图片/字体/埋点请求、缓存 Cookie 检查结论，减少对抖音的请求量
- **插件更新** — `#抖音更新` 拉取新代码并自动重启，更新前备份 `config/` 与 `data/`

## 安装

在 Yunzai 根目录执行：

- gitee

``` bash
git clone --depth 1 https://gitee.com/fox-glaze/hl-douyin-plugin ./plugins/hl-douyin-plugin
```

然后重启 Yunzai。

无需 `npm install`：依赖全部复用 Yunzai 自带的 puppeteer / express / node-schedule / yaml / lodash，插件自己不引入新包。

装好后 `#抖音更新` 就能拉取新代码并自动重启，不必再手动 `git pull`。

首次启动会自动生成：

- `config/config.yaml` — 只存你改过的项，默认值在代码里，插件升级后新字段自动补齐
- `data/secret.key` — AES-256-GCM 主密钥（0600），**丢了等于所有 Cookie 作废，备份时别漏**
- `data/accounts/<机器人QQ>.json` — 加密后的账号数据
- `data/audit.json` — 操作审计

整个 `data/` 已在 `.gitignore` 里。

## 续火好友与改名自愈

好友改名是断火最常见的原因，所以续火目标不是一个裸昵称，而是 `{ 主名, 别名[], 备注 }`：

- **主名** — 当前用于搜索的名称（抖音里的备注名优先于昵称）
- **别名** — 历史名 / 备用名，主名搜不到时按顺序试；命中别名会自动把它提为主名，下次直接用新名搜
- **备注** — 只用于展示（「表妹」「同事老王」），不参与搜索

三处都用同一套文本语法，指令、面板、锅巴写法一致：

```text
张三                    # 只有主名
张三(表妹)               # 带备注，全角括号与 ｜ 也认
张三三=张三              # 主名「张三三」，别名「张三」
张三三=张三=小三(表妹)    # 多别名 + 备注
```

旧版本的 `targetNames: ["张三"]` 在读盘时就地迁移成新结构，升级插件不需要任何手动操作。

## Cookie 传输方式

QQ 输入框会截断超长文本，而抖音的完整 Cookie 常常超过限制——贴进去就是残缺的。四条路径按可靠性排序：

1. **扫码** `#抖音登录` — 浏览器自动抓，最省事
2. **文件** `#抖音文件登录 账号名` + 发 txt — Cookie 很长时用这个。收到后解析完立刻删除临时文件（`security.deleteCookieFile`）
3. **锅巴 / Web 面板** — 「抖音账号与 Cookie」里一张卡片一个账号，粘 Cookie、配续火好友、开停用都在同一处
4. **粘贴** `#抖音手动登录 账号名 Cookie` — 短 Cookie 直接贴

第 2、4 条只能私聊。群里出现 Cookie 视为泄露：插件会尝试撤回并要求私聊重发。

## 锅巴里管账号

锅巴面板第一节「抖音账号与 Cookie」是个可增删的卡片列表，一张卡片就是一个抖音账号：

| 字段 | 说明 |
| --- | --- |
| 账号名称 | 指令与推送里指代这个账号，同一机器人下不能重名 |
| 机器人QQ号 | 账号归哪台机器人管，留空 = 当前在线的第一台。改这里等于把账号搬到另一台机器人下 |
| 账号ID | 只读，保存时生成。改账号名时靠它认出改的是哪一个 |
| Cookie 现状 | 只读，显示「已配置/已失效/未配置」与更新时间 |
| 粘贴 Cookie | **留空 = 不修改**。填了就替换，必须含 `sessionid`，格式不对当场报错 |
| 续火好友 | 顿号分隔，语法与指令一致（`主名=别名(备注)`） |
| 该账号的消息模板 | 留空则用全局模板 |
| 启用 / 备注 | 关掉则定时续火跳过该账号，账号与 Cookie 都保留 |

要点：

- **Cookie 永不回填**。面板是浏览器里的页面，回填就意味着密文随接口发到前端。所以那一栏打开永远是空的，只想改好友时不必重新粘一遍
- **删卡片 = 删账号**。删掉卡片并保存，该账号连同它的 Cookie 一起没了，不可恢复
- 账号数据不在 `config.yaml` 里，而在 `data/accounts/<机器人QQ>.json`（Cookie 为 AES-256-GCM 密文）。锅巴这一节直接读写它，与指令、Web 面板改的是同一份数据
- 校验先做完再落盘：某一行的 Cookie 格式或占位符写错，整次保存回滚，不会留下改一半的状态

`security.allowManualCookie` 关闭时这一栏拒绝写入（与 `#抖音手动登录` 同一开关）。

## Web 面板

发 `#抖音web` 后：链接发在当前会话，**6 位验证码只私信发**，两者分离才有意义。

流程：输入验证码 → 选择要操作的机器人 → 进入控制台（账号与发信 / 抖音登录 / 定时与推送 / 状态与审计）。

「定时与推送」标签页与锅巴改的是同一份 `config/config.yaml`，保存后定时任务立刻重新注册。

安全设计：

- 仅主人可触发；验证码只对「你是主人」的那些机器人授权，选别的机器人返回 403 并记审计
- 验证码一次性、默认 5 分钟过期，服务端只存 sha256，比较走 `timingSafeEqual`
- 验证码通过只换到一个会话，**不等于拿到机器人权限**——必须再显式选机器人，且不能越过授权名单
- 会话 Cookie 为 HttpOnly + SameSite=Strict，Path 限定在挂载路径下
- 验证码提交有独立限流桶（默认 60 秒 8 次），失败累计触发永久拉黑（重启或 `#抖音设置 解封IP` 清空）
- 所有敏感操作写审计，面板里可查
- 私信发送失败时自动作废刚发的验证码

面板默认挂在 Yunzai 自身端口的 `/douyin`。反代到公网时把 `web.url` 填成对外地址。`web.port` 填非 0 会额外起一个独立服务（端口被占用只警告，不影响插件加载）。

## 远程过验证

抖音在扫码确认后有时会追加一道身份验证（短信验证码 / 滑块）。这道验证必须由人在浏览器里点，而浏览器是无头的、跑在服务器上——插件的做法是把那个页面的**交互通道**转发给人，而不是自己去破解。

触发时：插件**私信**发起指令的那个人一个临时链接（外加一张现场截图），链接**绝不会出现在群里**。点开就能看到那台浏览器的实时画面，在图上点、按住拖、用输入框打字，和自己操作浏览器一样。验证过掉后 Cookie 照常落进同一个浏览器上下文，插件的主循环查到 `sessionid` 就自动保存——页面上会显示「登录成功」。

页面只支持人在浏览器里能做的物理动作：点击、双击、拖动、滚动、打字、以及 `Enter`/`Backspace` 等七个功能键。**没有执行任意脚本的入口**（那等于把远程代码执行开在公网上，而过一道验证根本不需要它）。

安全边界（与主面板完全隔离）：

- 链接**只私信**，不进群；发不出去就当场作废该链接
- 票据只能操作**这一次登录的那一个页面**：选机器人、增删账号、改配置、看审计一个都做不到，页面里也没有任何通往主面板的入口
- token 走 URL 的 hash（`/douyin/verify#t=xxx`）：hash 不发给服务端，不进 access log、不进 Referer；前端读完立刻 `replaceState` 抹掉，地址栏里也不留
- 接口只认请求头里的 token（`X-Verify-Token`），不接受 query——query 会被写进日志
- 默认绑定首次访问的 IP（`security.verifyBindIp`），链接被转发到别的机器就失效
- 猜 token 与猜面板验证码走同一套失败计数，累计到 `web.banAfter` 次拉黑该 IP
- 登录会话一结束票据即收尾（只留 1 分钟让页面读到「Cookie 已保存」这个结论）；同一次登录重复进验证态会作废旧链接，不会有多个同时有效
- 全程审计：`verify.issue` / `verify.open` / `verify.ip.denied` / `verify.close`。**只记操作次数，不记操作内容**——用户输进去的可能是短信验证码
- `#抖音web下线` 一并作废在外面飘的验证链接；`#抖音设置 会话` 可以看还有几个

不想用就把 `security.remoteVerify` 关掉，回到「报出验证类型 + 给文件登录/显形浏览器两条替代方案」的老路。

## 消息模板

留空 = 随机发一言（自带离线数据，无需联网）。

占位符：`{{account}}` `{{friend}}` `{{yiyan}}` `{{from}}` `{{date}}` `{{time}}` `{{weekday}}`

```text
{{friend}} 早上好，今天是 {{date}} {{weekday}}
{{yiyan}}
```

写错的占位符在保存时就会被拒绝，不会原样发给好友。yaml 里不方便换行可以写字面 `\n`。日期时间固定按 Asia/Shanghai 计算，服务器在国外也不会差一天。

账号可以单独设模板，覆盖全局那份。

## 安全说明

- Cookie 以 AES-256-GCM 加密存储，密钥在 `data/secret.key`（不用配置里的口令，因为口令会显示在锅巴面板上，密钥文件不会）
- 接口与日志里的 Cookie 一律打码
- 账号名、好友名进文件名前过滤，`../` 和盘符冒号都会被清掉
- 账号数据按机器人分文件，跨机器人读、删、跑都会失败
- 验证码、会话、IP 封禁全在内存里，**重启即全部失效**——对「主人临时开一次面板」的场景，这是安全收益
- 远程验证链接与面板是两套权限：链接只私信、只能操作那一次登录的页面、默认绑 IP、token 走 hash 不进日志，详见「远程过验证」一节

## 常见问题

**搜不到好友** — 用抖音里显示的备注名（备注优先于昵称）。对方改名时给目标加个别名（`#抖音加好友 账号名 新名=旧名`），下次搜到哪个都算命中；真删好友才会报「搜索不到」。

**Cookie 频繁失效** — 抖音单账号多端登录会互相挤掉。`#抖音检查cookie` 能确认；失效的账号在面板和状态图上标红，重新扫码即可。检查结论默认缓存 30 分钟，想立刻重查把 `spark.cookieCheckTTL` 调成 0。

**Cookie 粘不全** — QQ 输入框会截断超长文本。改用 `#抖音文件登录 账号名` 发 txt。

**二维码一直不出** — 未登录访问抖音首页时，登录面板是抖音自己弹的，插件只负责等它出现；实测从页面就绪到二维码渲染要 20 秒上下，所以 `security.qrLoginTimeout` 别调到 60 秒以下。

**报「未出现登录面板」** — 连面板都没等出来，二维码那一步还没轮到。报错里已经带了那一刻的页面现状（title / url / HTML 字节数 / img 数 / 一小段正文）和「点过登录入口」还是「连登录入口都没找到」的区分，先看这两处：HTML 只有几 KB、正文里有「验证」字样，就是被风控挡在了验证码中间页；HTML 正常大小但找不到登录入口，多半是抖音改了面板文案。想看得更细就 `#抖音设置 调试 开` 再扫一次，日志里会有每一步的结果；`#抖音设置 快照 开` 还会把整页截图与 HTML 存进 `data/debug/`，改选择器时对着它看。绕过去的办法是 `spark.headless` 改成 `false` 亲眼看一眼，或退回 `#抖音文件登录` / 手动导入 Cookie。

**扫码确认了但插件没反应，最后说超时** — 先看是哪一种。若停在「已收到扫码」：抖音的二维码约每 60 秒作废一张，页面会自己换新码，但 QQ 里发出去的那张图不会更新，扫作废的码永远等不到结果；插件现在检测到换码就补发一张新图并注明「上一张已过期」。若已经回过「已确认登录，正在取凭证」：抖音在扫码后追加了一道**身份验证**——实测截图里是一个标题为「身份验证」的弹窗，副标题「为保障账号安全，请先完成身份验证，以确保为本人操作」，下面两个选项「接收短信验证码」「发送短信验证」，二维码已被它整块盖掉。

这道验证必须由人在浏览器里点，但不用你亲自去服务器：插件会认出它，然后**私信**给你一个远程操作链接（外加一张现场截图），点开就能看着那台浏览器的画面把验证过掉，Cookie 照样自动保存，详见上面的「远程过验证」一节。进入验证态后等待上限自动放宽到 `security.verifyTimeout`（默认 10 分钟），够你收短信。

把 `security.remoteVerify` 关掉的话，还是老两条路：

1. **改用 `#抖音文件登录 账号名`** ——在你自己的浏览器里登录抖音，验证一次就过，把 `document.cookie` 存成 txt 私聊发过来
2. **把 `spark.headless` 改成 `false` 再扫一次** —— 浏览器窗口会显形在跑 Yunzai 的那台机器上，你自己在里面把身份验证过掉。这条路要求你能看见那台机器的桌面

**从头到尾停在「等扫码」，最后报「N 分内未完成扫码」，但你确实扫了也确认了** — 用的是旧代码，`#抖音更新` 拉一下即可。扫码状态靠拦 `check_qrconnect` 的响应判断，旧版把主机名和 `/passport/web` 前缀一起写进了匹配条件，抖音把这套接口搬到别的子域之后一条都拦不到：二维码还能从 DOM 里捞出来，所以出码、扫码这两步看不出异常，但之后所有状态都不会再变，最后按「等扫码超时」判死，验证链接自然也发不出来。现在判据只留接口名，且**认验证界面这一步完全不依赖任何接口**——每 2 秒直接看页面（连续两轮认出同一种才算，避免撞上首页推荐流的视频标题），所以状态卡在「等扫码」一样会发链接；判死之前还会再看最后一眼，认出来就改成发链接而不是报超时。

**远程验证链接打不开 / 一进去就说「验证链接无效或已过期」** — 三种可能：链接过了 `security.verifyTimeout`（默认 10 分钟）；被转发到了另一台设备（默认绑定首次访问的 IP，`security.verifyBindIp` 可关）；或者手机在 4G 与 WiFi 之间切换换了 IP——后者把 `security.verifyBindIp` 关掉即可。另外 `web.url` 必须填成对外可达的地址，否则链接里是内网 IP。

**页面打开了却什么都没有 / 标题是「验证码中间页」** — 无头 Chromium 的默认 UA 带 `HeadlessChrome`，抖音见到就返回一个 4KB 的验证码中间页，既没有登录入口也没有聊天列表。插件已在建页时把 UA 里的 `HeadlessChrome` 换成 `Chrome`，遇到这条说明用的是旧代码，`#抖音更新` 拉一下即可。

**报 `createBrowserContext is not a function`** — 装的是 puppeteer v22 之前的版本。插件已带兼容层自动退回旧 API，遇到这条说明用的是旧代码，`#抖音更新` 拉一下即可。

**配了群却没推送** — 先看 `push.target`：选了「仅群」时好友列表不收，反之同理。`#抖音状态` 的「推送范围」一栏就是当前生效值。

**改了 cron 没生效** — 不需要重启。插件自己持有定时任务，锅巴/面板/指令保存后会立刻重新注册；`#抖音状态` 里的「下次执行」就是当前生效的时间。

**面板打不开** — 检查 `web.enable`；反代后确认 `web.url` 填的是对外地址；`#抖音设置 解封IP` 可以解掉误触发的封禁。

**出图失败** — 会自动降级成文字，不会吞掉回复。想固定发纯文字就 `#抖音设置 渲染 关`。

**上面都对不上号，想知道到底停在哪一步** — `#抖音设置 调试 开`（或锅巴「排查」一节）再跑一次，Yunzai 日志里每一步都有一行 `[调试]` 前缀的记录：页面打开的 HTTP 状态、等的元素出没出现、拦到的接口与状态码、每轮验证探测的结论、状态流转、搜索命中的是主名还是别名。Cookie 的值一个字符都不会进日志，只记条数与名字。要连页面长什么样一起留证就再开 `#抖音设置 快照 开`，截图 / 纯文本 / 完整 HTML 按步骤编号存进 `data/debug/`（单页 HTML 常有一兆多，超过 `debug.keep` 个文件自动删最旧的）。查完记得关掉——调试日志会让日志量成倍增长。

## 实现取舍

**为什么不用 `plugin.task` 做定时** — loader 只在插件加载时读一次 `task.cron`，锅巴改完必须重启才生效。所以自己持有 `schedule.scheduleJob`，改配置后 `reschedule()` 立刻换表。

**为什么不复用渲染器的浏览器** — `renderers/puppeteer` 那个实例带自己的重启/超时策略，还会通过 redis 里的 wsEndpoint 跨进程共享。续火与扫码登录要持有分钟级的登录态页面，挂在它上面会被它的 restart 打断，也可能把抖音 Cookie 带进别的插件的截图上下文。这里只复用它的依赖（puppeteer 包）和 Chromium 路径配置，浏览器实例独立。

**为什么扫码登录要有 `confirmed` 这一档状态** — 手机点「确认登录」时抖音只是把 `redirect_url` 交给网页，`sessionid` 要等网页跳完那一趟才写进 cookie jar，实测差 1~3 秒。收到 confirmed 就立刻去读 Cookie 会读到空的，于是被判成失败。所以 confirmed 是独立一档：切状态、记时刻，交给主循环在 25 秒宽限期内轮询 Cookie，拿到就成功，拿不到就说清楚是抖音追加了验证而不是含糊地报超时。

**为什么登录页完全关掉请求拦截** — 抓过一遍登录页的请求：被 `BLOCKED_URL_PARTS` 命中的只有 slardar / mcs.zijieapi / mon.zijieapi / monitor_browser / webcast 这几类纯上报，passport 链路（`challenge` → `get_qrcode` → `check_qrconnect`）一个都不在里面，也就是说拦截并不是登录卡死的原因。但登录一辈子只跑几次，省这几十个请求收益为零，而那份清单以后多一条命中 passport 的规则，整条登录链就会静默挂掉。收益为零、风险是整条链路，所以干脆不挂。

**为什么扫码登录没嵌入现成项目** — 备选项要么自带一整套浏览器栈（Playwright，本仓库没装），要么是 Rust/Java 独立进程，要么走逆向签名接口。而抖音扫码本身就是两个公开接口：`get_qrcode` 出图、`check_qrconnect` 出状态，在我们自己的 puppeteer 会话里拦这两个响应就能拿到二维码和结果，Cookie 直接落在同一个 browserContext 里，不需要第二套浏览器或新依赖。

**为什么必须改 UA** — 无头 Chromium 自报的 UA 里带 `HeadlessChrome`，抖音直接返回标题为「验证码中间页」的 4KB 空页；换成 `Chrome` 后同一份代码拿到的是完整首页（1.4MB，登录面板自动弹出）。这里不硬编码某个 UA 字符串，而是取浏览器自报的 UA 只替换这一个词——写死的版本号会随时间变旧，反而更容易被识别，而且平台信息与真实内核不一致也是特征。

**为什么不去点「登录」按钮** — 原本的做法是找文本为「登录」的叶子节点再逐层往上点，抖音改一次 DOM 就失效。实际上未登录访问首页时抖音自己就会弹出扫码面板，插件只需要等：先等「扫码登录/验证码登录/密码登录」这组文字或二维码 img 出现，等不到才退回主动点击。少一个对页面结构的依赖。

**为什么多账号是串行跑** — 并行会同时开多个 Chromium，既吃内存又容易触发抖音风控。

**为什么 puppeteer 的调用要探测再用** — Yunzai 根 `package.json` 里 puppeteer 写的是 `"*"`，实际装到哪个大版本取决于用户机器，而这几个 API 各改过一次名字或位置：

| 用途 | 新 API | 旧 API |
| --- | --- | --- |
| 建隔离上下文 | `browser.createBrowserContext()`（v22+） | `createIncognitoBrowserContext()` |
| 写 Cookie | `context.setCookie()`（v23+） | `page.setCookie()` |
| 读 Cookie | `context.cookies()`（v23+） | CDP `Network.getAllCookies` |
| 连接状态 | `browser.connected`（v22+） | `browser.isConnected()` |

写死新 API 在装了旧版的机器上就是 `createBrowserContext is not a function`，所以 `lib/browser.js` 顶部有一层探测分派。读 Cookie 的旧路径特意走 CDP 而不是 `page.cookies()`：后者只返回当前 URL 域下的 Cookie，而扫码会在 `douyin.com` 与 `sso.douyin.com` 之间跳，漏子域等于丢 `sessionid`。

**为什么 `index.js` 只做导入** — loader 的 `getPlugins()` 见到插件目录里有 `index.js` 就只导入它并跳过其余 .js（`lib/plugins/loader.js:56`），所以指令想拆文件必须由 index.js 自己扫 `apps/` 并导出 `apps` 对象（`importPlugin()` 会把 `app.apps` 摊平）。键名用 `文件名.导出名`，一个文件里放多个插件类也不会互相覆盖。

**为什么 `applyConfigChange` 写成箭头函数** — loader 只用 `if (!p?.prototype) return` 过滤非插件导出，普通 `function` 有 prototype，会被当成插件类 new 两次然后读 `rule.length` 报错。箭头函数没有 prototype，正好被过滤掉。

**为什么文件登录单开一条指令** — 复用 `#抖音手动登录` 的话，它的正则会把后续参数吞进 Cookie 位置。而 loader 的 context hook 优先于 rule 匹配（`loader.js:205`），`#抖音文件登录 账号名` 挂上下文后用户发的下一条消息（带 `e.file`）会直接进回调，语义更干净。

**为什么锅巴删账号靠快照对比** — GSubForm 删卡片在前端就是把那一项从数组里 splice 掉，提交上来只是「少了一行」，光看内容分不清「用户删了它」还是「它是保存期间新扫码进来的」。所以把发给锅巴那一刻的账号 id 记成快照，只有当时在、这次不在的才算删除。另外锅巴的 `handleFormValues` 会把空数组字段整个丢掉，删光所有卡片时收到的是 `undefined` 而不是 `[]`，所以按 `data.accounts || []` 处理——用 `"accounts" in data` 判断的话最后一个账号永远删不掉。

**为什么远程验证不复用面板会话** — 面板会话一建立就能选机器人、增删账号、改配置、看审计，那是「管理整套插件」的权限。而验证链接只有一个用途：让人把抖音那道身份验证点过去。两者权限差一个数量级，链接又要落在公网可达的地址上，混用等于把管理面板的钥匙塞进一次性验证链接里。所以票据（`lib/remote.js`）、路由（`/api/verify/*`，绕开 `requireAuth`）、页面（`web/verify.html`，独立单文件、不引 app.js、没有任何通往面板的入口）全部另开一套。

**为什么远程操作只转发物理动作** — 只支持点、双击、拖、滚、打字、七个功能键，不提供 `evaluate` 之类能跑任意脚本的入口。那等于把远程代码执行开在公网上，而过一道验证根本用不到它。同理不做通用键盘：`ALLOWED_KEYS` 只放通过验证真正需要的那几个。

**为什么坐标传 0~1 而不是像素** — 前端那张图会被 CSS 缩放（手机屏幕比 1280 窄得多），一旦两边对缩放比的理解差一点点，点击就会偏——而偏一点点在「验证码输入框」和「换一张」之间就是天壤之别。归一化之后前端只需要 `offsetX / 元素宽度`，服务端只需要乘 viewport，中间少一个必须两边对齐的约定。

**为什么拖动要连时间戳一起重放** — 滑块验证判的就是那条曲线，代码生成的匀速直线基本过不去。前端录的是用户真手拖出来的轨迹（含每点的相对时刻），服务端用 `page.mouse.move()` 按原节奏逐点重放，过的是真人轨迹。单步间隔夹在 0~120ms：既保住真实节奏，也不让一条轨迹把请求拖到几分钟。

**为什么帧用 jpeg 不用 png** — 同一帧 png 约 300KB、jpeg 质量 60 约 40KB。前端每秒拉一张，差出来的带宽在公网反代下很明显，而这张图只是给人看清按钮在哪，不需要无损。

**为什么登录结束不立刻撕票** — 页面就在人手上开着，验证刚点完那一秒后端就把票撕了的话，前端下一次拉帧收到的是 401「链接失效」，而真实结果恰恰是「Cookie 已存好了」。所以 `closeBySession` 只标记收尾并把期限压到 1 分钟，让页面把最终结论读到手；这段窗口里取帧和操作都会因为 page 已关闭而失败，读不到别的东西。

**为什么更新前要备份整个 `config/` 与 `data/`** — 参考实现只备份单个 yaml，但本插件 `data/secret.key` 一旦被 `git reset --hard` 冲掉，所有已保存的 Cookie 都永久解不开。恢复时只写回「pull 后不存在」的文件，不覆盖新代码带来的内容。
